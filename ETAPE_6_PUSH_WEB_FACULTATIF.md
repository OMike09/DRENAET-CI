# DRENAET CI — étape 6 : push web facultatif et confidentiel

## Portée réelle

Le colis 6 ajoute un **avis push web générique**, uniquement après action volontaire « Activer sur cet appareil » dans Mon profil. Il couvre les nouvelles alertes internes des instructions, missions, messages privés, rapports, bibliothèque et calendrier créées **après abonnement**. Le push ne contient ni nom, ni texte de message, ni document, ni détail pédagogique : pour consulter l'alerte, il faut ouvrir l'application et s'authentifier. Le service worker ouvre la page Notifications ; l'historique interne, ses autorisations et ses états « Ouvert » restent la source de vérité. Le push peut regrouper des avis visuels, sans effacer les alertes internes.

Les abonnements (endpoint et clés de navigateur) sont privés en PostgreSQL, rattachés à **une session authentifiée** ; ils sont supprimés à la déconnexion, lors de suspension, réaffectation, réinitialisation ou changement de mot de passe ; ils expirent avec la session (12 heures, sans renouvellement implicite) et peuvent être révoqués depuis le profil. Cinq appareils maximum par compte. Une inscription ultérieure exige une nouvelle action explicite ; aucun ancien compte ou événement n'est abonné/notifié rétroactivement. L'audit conserve le consentement et la révocation, sans endpoint ni clés.

La migration 006 ajoute la file des envois dans les **mêmes transactions** que les alertes internes ; un échec de l'opération source ne produit aucun envoi. Le processus Node traite la file après validation, vérifie encore le compte, la session et l'accessibilité avant un envoi, retente certains échecs de transport au plus cinq fois et retire l'abonnement sur réponse 404/410 du fournisseur. Un envoi peut être répété en cas de panne entre l'expédition et l'accusé en base ; aucun accusé fournisseur ne prouve la réception sur le téléphone. Le service worker ne lit pas les contenus de la file et ne tente aucune notification sans événement push.

## Configuration privée et activation

1. Installer les colis **1 à 5 avant le colis 6**, après inventaire, sauvegarde de la base réelle et essai de restauration. Déposer uniquement les fichiers du delta 6 en conservant les chemins existants ; `npm install`, puis redémarrer ou redéployer le Web Service Node. La migration 006 est appliquée automatiquement au démarrage avec une connexion PostgreSQL **directe non poolée**. Aucune valeur de `DATABASE_URL` n'est demandée.
2. Générer une **nouvelle paire VAPID** hors du dépôt avec le module `web-push` (`node -e "console.log(require('web-push').generateVAPIDKeys())"`). Ne pas envoyer la clé privée dans cette conversation, un ZIP ou GitHub. Configurer **dans l'environnement privé du service** `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` et `VAPID_SUBJECT` (adresse `mailto:` de contact administratif valide). Ne pas utiliser une clé anciennement exposée. Les trois valeurs doivent être cohérentes ; configuration partielle = démarrage refusé. Sans ces valeurs, l'application et les notifications internes fonctionnent, mais le bouton push reste indisponible.
3. Utiliser HTTPS, une origine stable et un navigateur compatible. Le colis contient un manifeste d'installation et des icônes locales ; sur certains iPhone, l'installation du site sur l'écran d'accueil peut être nécessaire. Cela ne prouve pas la compatibilité d'un appareil précis. Depuis Mon profil, **chaque personne** demande elle-même la permission et active l'appareil. Vérifier une désactivation volontaire, une déconnexion, une suspension, la réactivation après nouvelle connexion, et le cas du téléphone verrouillé / de l'application fermée avec des comptes de test autorisés. Ne pas conclure au fonctionnement sur Android ou iPhone depuis les seuls tests simulés.

**Hébergement gratuit :** le traitement est réalisé dans le processus Node, environ toutes les 15 secondes *lorsqu'il tourne*. Un service Render gratuit mis en veille ne garantit ni délai ni livraison hors application ; la file persiste en base et reprend au réveil, sous réserve d'une session encore valide. Aucun SLA, son, vibration, courriel ou push natif APK n'est promis. La portée des hôtes de fournisseurs acceptés est volontairement limitée aux services courants Apple, Google/FCM, Mozilla et Windows ; d'autres navigateurs peuvent être rejetés. Aucune réception distante ni autorisation réelle de téléphone n'a été testée par l'agent.

## Validation locale

- Test de la migration 005→006 sans perte ni push rétroactif ; tests PostgreSQL de consentement, isolation, file transactionnelle, absence de corps privé, instructions et messages, suspension, révocation, erreur 410 et redémarrage.
- Parcours Chromium mobile **simulé** : permission demandée seulement après clic, activation, désactivation, fermeture de session. Le service push réel et un téléphone physique sont **simulés ou absents** ; ces tests ne valident ni délivrance réelle ni comportement iOS/Android.
- Exécution complète : `AC_RUN_BROWSER_TESTS=1 TEST_DATABASE_URL=<base PostgreSQL locale de test> npm test` : **19/19 tests réussis**. `npm audit --omit=dev --audit-level=high` : **0 vulnérabilité signalée**.

## Limites et sécurité opérationnelle

Ne pas lancer les tests sur la base de production. Les anciens contenus privés restent protégés par les mêmes autorisations serveur ; la réception d'un signal générique ne confère aucun droit supplémentaire. Pas d'indicateurs pédagogiques d'élèves en v1. Si la base de production ou le dépôt ne contient toujours que les premières étapes, **ne pas installer directement ce delta** : d'abord vérifier le code réellement déployé et appliquer les étapes intermédiaires après sauvegarde et accord. Aucune installation sur Render/Neon ni test push réel n'a été réalisé pour cette livraison.
